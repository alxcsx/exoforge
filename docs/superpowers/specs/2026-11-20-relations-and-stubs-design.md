# Relations (EF-style Include) and explicit stub generation

## Why
Resources reference each other (loja_ofertas.item_id -> itens.id, owned by another extension). Code should navigate that like an ORM,
with permissions, and stubs for service calls should exist for every non-excluded extension without making Unity slower or fragile.

## Decisions (from the user)
- `Include` works on resource classes, Entity Framework style; cross-extension relations are resolved **at query time on the host with permissions**; the UI side stays lazy.
- No new rule system: the existing FK declaration `[ExoColumn(ForeignKey = true, References = "itens.id", ReferencesType = typeof(Item))]` is the rule.
- Stubs are never generated by MSBuild or by Unity (import, domain reload, project load). Only explicit actions (CLI, Unity window buttons) run generation.
- Dependencies come from implicit usage (`ExoServices.<Service>`), already inferred by the Roslyn generator into manifest `dependencies`; `[ExoDependency]` is only a pin.

## Contract A: host include (Elixir, extensions/exoforge_std_database + lldb)
`database.execute` payload gains optional `include: [{"column": "<fk column of the root table>"}]`.
Response gains `included: {"<column>": {"<fk value>": <referenced row as json>}}`. Host flow: run the root query as today; for each include, check that
the column is a declared FK in the CALLER's resource (manifest `foreign_key`+`references`), that the referenced resource exists (owner may be another extension),
collect the distinct non-null values, fetch them with ONE query in the owner's schema (`WHERE pk = ANY($1)`), and return them. Permissions: if the original caller
is a player (context scopes), the referenced resource must be player-readable (same rule resource_store uses for `AllowPlayerRead`); server/studio/internal callers are allowed.
Unreadable or missing rows are simply absent from `included` (the navigation stays null). Unknown/undeclared column -> error `invalid_include`. Referenced extension not deployed -> `included` omits it and a `missing_reference` warning is returned, never a crash.
Non-goal now: filtering/ordering by a joined table's columns.

## Contract B: SDK ORM (Exoforge.Plugin.SDK, Exoforge.Plugin.Generator)
- Explicit pairing, no naming convention. The FK is a normal column: `[ExoColumn(ForeignKey = true, References = "itens.id", ReferencesType = typeof(Item))] public string ItemId { get; set; }`.
  The navigation is a virtual property that exists only because of `Include`: `[ExoNavigation(nameof(ItemId))] public Item? Item { get; set; }` (new, tiny attribute whose only argument is the FK property).
  A navigation is not a column, is not stored, is not sent to the host and is not serialized; it is null until an `Include` fills it. The generator/SDK reject a navigation whose FK property is missing or not a declared FK, with a clear message.
- `table.Include(o => o.Item).Where(...).ToList()` (several Includes allowed) sends `include` to the host and fills the navigation properties from `included` (same-extension FKs use the same path).
- `table.Include(entity, o => o.Item)` / existing `Include<TRef>(entity, fk)` keep working, now through the same host path; they throw a clear error instead of returning null silently.
- Fix review findings in .agents/handoff/review-B-F3-shop.md: builder is immutable per call, Count ignores Take/Skip -> make it correct, Skip without Take, in-memory test database must not silently ignore SQL.

## Contract C: explicit stubs (Management, CLI, Unity Editor)
- `exo extension stubs --all`, and `build|push` (single or `--all`) run the stub pass first for the extension(s). Output: `<ext>/obj/exoforge/PluginServices.g.cs` (never `src/Generated`, not committed). The package build targets only `<Compile Include="obj/exoforge/**/*.cs" Condition="Exists(...)"/>`; no process runs in MSBuild.
- Scope: every non-excluded extension; providers first; contracts for siblings from their manifests, built-in services from the contracts cache or the server.
- Dependency discovery without a manifest: scan sources for `ExoServices\.(\w+)` (Pascal -> snake service name, matched against siblings' names/provides and the cache) plus `[ExoDependency("x")]` pins; ValidateIncluded (exclusions) uses the same discovery.
- Unity: Build / Build & Deploy All call the same Management code. Nothing runs from `InitializeOnLoad`, AssetPostprocessor or domain reload. Any failure surfaces as a status banner, never an exception during load.
- Remove committed `src/Generated` from the arcade (brainrot_market, loja_itens, inventario) and gitignore it.

## Out of scope
SQL JOIN-based filtering across extensions; lazy-loading proxies.
