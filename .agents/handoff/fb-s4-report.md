## Builtin Elixir Extensions & priv/manifest.json Source of Truth
- **Source of truth**: For Elixir extensions, service contracts (actions, params, returns) are defined in Elixir code (`core/lib/std/services.ex`), not in `priv/manifest.json`. `priv/manifest.json` is generated by `Mix.Tasks.Compile.ExoforgeManifest` and carries metadata + `provides`, but `"services": []` (no actions).
- **Stub generator effect**: `exo extension stubs` successfully scans `extensions/*/priv/manifest.json` in-repo and resolves `file_bucket` dependency into `obj/exoforge/PluginServices.g.cs`. However, because `priv/manifest.json` has `"services": []`, the emitted `IFileBucketService` has no actions, so callers requiring `FileBucketSetBucketVisibilityRequest` fail at C# compile time.
